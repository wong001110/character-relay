# Character Relay Discord Connector

This worker connects one official Discord Bot account to Character Relay deployments.

## Current MVP

- Discord Gateway connection through `discord.js`.
- Active deployment routing by Discord Server, Channel, and optional Thread.
- Mention-only, reply-only, and mention-plus-reply trigger modes.
- Smart Participation remains explicitly opt-in and disabled by default.
- Small in-memory per-destination context buffer.
- Per-channel serial processing to prevent overlapping character replies.
- Duplicate-message protection.
- Character Relay heartbeat and deployment refresh.
- Railway-compatible health endpoint and container.
- Responses are generated by the deployed Character Card without a runtime OOC judge.

The connector currently sends replies through the shared Bot identity and prefixes the message with the Character Card display name. Character-specific webhooks, Discord sticker selection, slash-command setup, and long-term group memory remain later phases.

## Discord application setup

Create a Discord Application and Bot in the Discord Developer Portal. Invite it to the target Server with these minimum permissions:

```text
View Channels
Send Messages
Send Messages in Threads
Read Message History
```

Use the `bot` and `applications.commands` OAuth scopes. Administrator permission is not required.

The default MVP does not require the privileged Message Content Intent because it only expects explicit Bot mentions or replies. Enable Message Content in the Developer Portal and set `DISCORD_MESSAGE_CONTENT_INTENT=true` only when testing full-channel observation or Smart Participation.

## Character Relay setup

1. Add a Discord connection in the Character Relay Deployment Center.
2. Copy the resulting Connection ID.
3. Create one or more Active deployments using that connection.
4. Configure the same shared connector secret in the API and worker:

```text
Character Relay API
ECHO_MASQUE_CONNECTOR_SHARED_SECRET=<long random secret>

Discord Connector
CHARACTER_RELAY_CONNECTOR_TOKEN=<same secret>
```

Each deployment must use the Discord parent Channel ID. For a Thread deployment, also set the exact Thread ID. Channel and Thread deployments are independent records.

## Local development

Requires Node.js 24.17 or newer.

```bash
cd connectors/discord
npm install
cp .env.example .env
npm run dev
```

Required variables:

```text
DISCORD_BOT_TOKEN
CHARACTER_RELAY_API_URL
CHARACTER_RELAY_CONNECTOR_TOKEN
CHARACTER_RELAY_CONNECTION_ID
```

## Railway deployment

Create another Service in the same Railway Project and set its Root Directory to:

```text
/connectors/discord
```

Railway will use the local `Dockerfile` and `railway.toml`. Keep one replica because one Bot token should have one active Gateway consumer in this MVP.

Set:

```text
DISCORD_BOT_TOKEN=<Discord Bot token>
CHARACTER_RELAY_API_URL=https://<Character Relay service domain>
CHARACTER_RELAY_CONNECTOR_TOKEN=<shared secret>
CHARACTER_RELAY_CONNECTION_ID=<Connection ID from Deployment Center>
```

The worker exposes `/health` and reports whether Discord is ready, how many deployments are cached, the last deployment refresh, and the last connector error.

## Trigger behavior

```text
mention_only
  Reply only when the Bot is mentioned.

reply_only
  Reply only when a member replies to a message sent by the Bot.

mention_and_reply
  Accept either explicit trigger.

smart
  Behaves like mention_and_reply by default.
  Full-channel submission requires DISCORD_SMART_PARTICIPATION_ENABLED=true
  and usually DISCORD_MESSAGE_CONTENT_INTENT=true.
```

Smart Participation is deliberately conservative in the first release. A later Social Participation Engine should decide whether the character should intervene instead of treating every visible message as a reply request.
